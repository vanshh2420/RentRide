## 2. Missing & Potential Features (Gap Analysis)

Based on the actual codebase audit, the following items are categorized by their logical relationship to the existing system:

### A. Missing Functionality Required for Existing Flows
1. **Automated Gateway Refund API Execution**: When a booking is cancelled via [`cancelBooking`](file:///c:/Users/vansh/OneDrive/Desktop/Project/RentRide/server/src/services/booking.service.js#L350), refund calculations and database updates are recorded, but direct HTTP dispatch to `razorpay.payments.refund()` is not yet executed automatically.
2. **Automated Expiry Sweeper for Checkout Locks**: While expired locks (`lockExpiresAt < now`) are ignored by query conditions in `isVehicleAvailable`, an automated cron job or MongoDB TTL index would permanently revert orphaned `PENDING_PAYMENT` bookings to `EXPIRED`.

### B. Logical Follow-up Features
1. **Email / SMS Notification Dispatch**: Currently notifications are purely in-app database records ([`notification.model.js`](file:///c:/Users/vansh/OneDrive/Desktop/Project/RentRide/server/src/models/notification.model.js)). Adding Nodemailer or Twilio integration for booking vouchers and OTPs would complete the offline-to-online loop.
2. **Interactive Map Pickup Pinpoint**: Vehicle location models store `{ lat, lng, address }` ([`vehicle.model.js`](file:///c:/Users/vansh/OneDrive/Desktop/Project/RentRide/server/src/models/vehicle.model.js#L58-L66)). Integrating Leaflet or Google Maps onto the Explore and Vehicle Details page would provide visual navigation.
3. **Vendor Payout Settlement Ledger**: Currently vendor payouts are calculated per booking (`vendorPayout`), but a formal payout disbursement request / bank transfer tracking module is not present.

### C. Enhancements
1. **Live GPS / Telematics Tracking**: Integration of IoT OBD/GPS devices for live speed, battery status, and fuel levels during active rentals.
2. **Automated AI Model Re-training Pipeline**: Currently the AI microservice uses rule-enhanced statistical engines (cosine similarity and heuristic multipliers); background batch training on historical booking datasets can be added as data accumulates.

### D. Optional Improvements
1. **Social OAuth Login**: Google / Apple One-Tap authentication alongside existing email/password JWT auth.
2. **Multi-Language / Localization Support**: Multilingual support for Hindi and English across regional operating hubs.
